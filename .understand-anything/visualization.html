llm-from-scratch-lab

A decoder-only language model built from scratch in PyTorch, trained on TinyStories, with a closed-form scaling estimator and a calibration study showing where the published formulas break — and fixing them.

💡 Why this project

📚

CS336 inspiration

Inspired by Stanford CS336 (Spring 2025), an independent reimplementation — not coursework. Goal: understand every component by building it, not importing it.

🔬

The real question

Most "GPT from scratch" repos stop at a working model. The interesting questions are in the assumptions model: where does the back-of-envelope agree with reality, and where does it break?

⚡

MacBook feasible

Everything runs on a MacBook — no cloud required for the core results. Apple MPS backend, ~13 min to train, ~2 GB data download.

📉

Calibration study

The JAX Scaling Book estimator was wrong by 65–154% on real hardware. This repo documents exactly why and proposes four fixes, implementing two — cutting MAE from 64% → 29%.

🔧 What it does — three stacked artifacts

🤖

Artifact 1 — Working LM

A correct, tested, end-to-end decoder-only transformer trained on TinyStories. Feed it the start of a sentence; it finishes the story. Loss: 245 → 2.87, val perplexity ~20.

📐

Artifact 2 — Estimator

Pure-Python closed-form formulas for parameters, FLOPs, activation memory, KV cache size, decode latency, and training time. No torch dependency — runs in microseconds.

📊

Artifact 3 — Calibration study

torch.profiler benchmarks on CPU + MPS measured against estimator predictions. Found systematic errors, proposed fixes, verified improvements. The engineering content lives here.

⚙️ How it works

🔤

Tokenization

Byte-level BPE trained on a 5 MB sample of TinyStories. GPT-2 pretokenization pattern, tie-break by lex order. Vocab size 10,000. Saves as vocab.json + merges.txt.

🧠

Transformer core

Pre-norm architecture: RMSNorm → CausalMHA (RoPE, tril mask) → residual → RMSNorm → SwiGLU FFN → residual. CS336 A1-compatible state_dict keys.

🏋️

Training

Custom AdamW (decoupled weight decay), cosine LR schedule with linear warmup, gradient clipping (max L2 norm), checkpoint save/load, validation perplexity every N steps.

📡

Profiling

torch.profiler harness sweeps seq_len × batch_size grid. Warmup + timed steps, Chrome-trace export. Results written to results/local/sweep.json.

🧮

Estimator

Closed-form from the JAX Scaling Book. Computes params, FLOPs, activation memory, KV cache, decode latency lower bound, train time, roofline threshold.

🖥️

Streamlit explorer

5 Plotly tabs with provenance labels (Simulated / Measured / Hybrid). Sidebar sliders control ModelSpec / RuntimeSpec / HardwareSpec live.

Finding 1 — Overhead floor missing

The estimator assumed zero fixed per-step launch overhead. On CPU at small batch sizes, the actual step time is dominated by Python + BLAS dispatch latency (~1–5 ms), not by memory bandwidth. Fix: add an overhead_floor_s parameter that caps predicted tokens/s when step time would otherwise be implausibly short.

Finding 2 — Roofline gate missing

The original formula was purely memory-bound (bandwidth denominator only). At high batch sizes or long sequences, arithmetic intensity crosses the roofline threshold and the kernel becomes compute-bound. Fix: predict_tokens_per_second_v2() computes intensity = FLOPs/bytes and picks the tighter of compute-bound and memory-bound predictions.

Finding 3 — Two more fixes proposed (not yet implemented)

Fix 3: account for non-uniform operator mix (attention is more memory-bound than matmuls; a single roofline threshold is too coarse). Fix 4: calibrate MFU empirically per device rather than using the 0.4 default, which varies significantly across hardware generations.

Bottom line: The JAX Scaling Book formulas are excellent first-order estimates but systematically wrong on real hardware in two predictable ways. This repo makes the failure modes explicit, quantifies them, and shows that two targeted fixes roughly halve the error without increasing formula complexity.
